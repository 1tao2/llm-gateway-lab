# 参考生视频模型测试

按可复现、可审计的方式完成一批参考生视频测试。

## 首次调用与信息引导

用户只要调用本技能并表达要测试某个模型，即使信息不完整，也要先帮助其完成测试输入，不得只回复“缺少信息”或要求用户自行阅读规范。

1. 先从用户消息、附件和仓库已有实现中提取已经提供的信息，不重复询问。
2. 将缺失项按“预检必需”“真实执行前必需”分组列出，并给出下面的可复制模板；允许用户分多次补充。模板中每个字段冒号后的填写说明必须保留在代码块内，不得缩写为空字段、移到模板外或改成笼统说明。
3. 若用户暂时没有 API 文档，可先说明能够完成哪些本地预检；新模型没有可核验调用依据时不得真实调用。
4. 信息足够预检时直接预检，不再要求用户重填模板。
5. “先预检”不授权上传或付费调用；只有用户明确要求“开始执行、完整执行、生成或重跑”时，才进入真实调用。

本地结构预检必需信息：

- 厂商和 `model_name`。
- 提示词文件：应包含待测试分镜的 `scene_index` 和非空 `scene_video_prompt`；每个分镜的 `scene_index` 应唯一，Prompt 中使用 `<<<资产名>>>` 引用参考资产。
- 本地资产目录：被引用资产的文件名（不含扩展名）必须与 `<<<资产名>>>` 严格一致；例如 `<<<福娘>>>` 对应 `福娘.jpg` 或 `福娘.png`。同一资产名不得同时存在多个不同扩展名文件。
- 测试分镜范围。
- 分辨率、`ratio`、时长策略、声音策略和最大并发数。声音策略必须说明是否开启音画同出，或按分镜明确 `audio=true/false`；无对白不自动等于静音。模型不支持某项开关时记录为省略，不伪造参数。

新模型完成能力限制预检及真实执行前，还需官方 API 文档链接；登录可见时提供脱敏的创建/查询请求示例或字段截图。真实执行前另需确认测试范围与费用授权，以及凭证已经通过项目安全配置提供。不得要求用户粘贴 API Key、AccessKey、Token 或认证 Header。

向信息不完整的用户返回此模板，并只删除已经提供完整的整行字段。其余字段必须原样保留字段名、示例、格式约束和选项说明：

```text
使用 reference-video-model-test 测试新模型。

厂商：
model_name：
官方 API 文档：
创建/查询请求示例（文档公开时可省略）：
提示词文件：包含唯一 scene_index 和非空 scene_video_prompt；资产引用写作 <<<资产名>>>
资产目录：文件名（不含扩展名）与 <<<资产名>>> 严格一致；同名资产只保留一个文件
测试范围：全部分镜 / scene_index ...
分辨率：
ratio：例如 16:9 / 9:16 / 1:1；以模型支持值为准
duration：按 scene_video_prompt 适配 / 指定策略
声音策略：开启音画同出（audio=true）/ 关闭音画同出（audio=false）/ 按分镜指定 / 使用模型固定能力
最大并发数：
执行阶段：先预检 / 完整执行并生成报告
```

## 开始前

1. 阅读仓库根 `AGENTS.md` 和 [测试规范](../../../docs/reference_video_model_test_standard.md)。涉及 `clients/` 或 `services/` 变更时继续读取对应目录的 `AGENTS.md`。
2. 检查当前工作树，保留无关用户修改。
3. 收集 Prompt 文件、资产目录、厂商、模型、分镜范围、分辨率、`ratio`、时长策略、声音策略和并发数。
4. 新模型、新版本或新厂商必须取得可核验的 API 调用依据：优先使用用户提供的官方文档；文档仅登录可见时，要求提供脱敏的创建/查询请求示例或字段截图。仓库已接入且调用契约已验证的模型可复用当前 Client/Service，无需用户重复提供文档。
5. 核对官方文档和仓库调用链；模型能力、价格、默认值等不凭记忆判断。没有可核验调用依据时只做 Prompt 与资产预检，不猜测字段或发起付费生成。
6. 不要求用户提供 API Key、AccessKey、Token 或完整认证 Header；凭证只使用项目已有的安全配置。

## 执行边界

- 预检、报告生成和读取已有任务是只读或本地操作。
- 上传资产、创建生成任务和转存结果是外部副作用。只有用户明确要求开始、执行或重跑测试后才能进行，并只处理其指定范围。
- 不打印或写入凭证、认证 Header、完整 Base64。
- 创建结果不明确时先查 Task ID，不盲目重提；失败后不擅自修改 Prompt、音频、时长或种子重跑。

## 工作流

1. 使用 `scripts/preflight_reference_video_test.py` 生成测试 manifest；用户指定分镜范围时通过可重复的 `--scene-index` 精确筛选。缺图、同名多文件、时长不明或模型限制不满足时停止真实调用。
2. 按 manifest 冻结每镜资产首次出现顺序。并行上传不得改变媒体编号。
   模型要求受审素材时，使用技能内素材准备器完成并发素材审核和 `asset://` 注册。真人素材统一传 `IsRealPerson=True`，必须由用户本人完成 H5 活体认证并复用其返回的 `GroupId`，Token 不写报告；非真人素材传 `IsRealPerson=False`，使用测试批次稳定的自定义 `GroupId`，不得误走活体认证。
3. 新模型按官方文档生成单次测试用的脱敏 `call_spec.json`，格式见 [声明式调用规格](references/call-spec.md)。简单 JSON API 使用 `http`，仓库已有复杂签名 Client 使用 `project_client`；只有两者都无法表达时才新增协议级代码适配器。
4. 使用 `scripts/run_reference_video_test.py --validate-only` 离线核对 Prompt 转换、媒体数组和实际请求结构；验证通过后保存脱敏请求快照。
5. 显式记录每镜音频策略。无对白不自动等于静音；以用户策略为准。
6. 获得真实执行授权后，使用同一个 `scripts/run_reference_video_test.py` 在授权并发数内上传、创建和轮询；不得为每个模型复制 runner。创建结果不明确时保留 `CREATE_UNKNOWN` 并停止自动重提。
7. 成功视频转存稳定 OSS，记录厂商时间字段和 usage。
8. 将任务结果写成 [结果数据契约](references/data-contracts.md)，再用 `scripts/build_reference_video_report.py` 生成 Markdown 报告。
   同一模型版本的测试使用可重复的 `--suite-case <测试组名> <manifest> <results>` 生成一份综合报告；多个剧本、分辨率或其他参数组合在报告内拆成测试组，不能仅因 `scene_index` 重复而覆盖结果。不同模型版本（例如 lite/pro）分别生成报告，不跨版本合并。
9. 使用 [问题分类](references/issue-taxonomy.md) 记录人工评测；交付时说明成功率、耗时统计、重跑变体和未执行项。

## 交付检查

- 每个分镜在报告中并列展示转换前的 `scene_video_prompt` 原值和转换后的实际提交 Prompt，并披露 `<<<资产名>>> → 图N` 映射及参考资产顺序。
- 报告至少含精简资产表（资产名、文件名、上传后的稳定 OSS 链接、引用/输入方式，不披露图片格式、尺寸、文件大小等技术信息）、任务结果、稳定视频、排队/执行/总耗时和问题列；任务表不展示状态和 Audio 列。
- Prompt 转换前后全文直接展开，不使用 `<details>`、`<summary>` 等折叠标签；不生成单独的“实际请求转换与执行口径”章节。
- 每个分镜明细采用紧凑连续结构：分镜标题、生成视频 URL、资产转换、转换前 Prompt、转换后 Prompt；这些元素之间不插入空行。
- 同一模型版本包含多个剧本时只保留一份覆盖全部任务的综合耗时统计，不在各剧本明细中重复生成耗时统计。
- 同一剧本使用相同资产和 Prompt 测试多个分辨率或参数组合时，资产表和 Prompt 明细只展示一次；各生成视频与任务结果标注对应测试配置，不按配置重复生成剧本章节。
- 同一分镜有多个重跑变体时，在该 Prompt 明细中列出全部视频 URL 和变体名，不覆盖旧结果。
- 校验报告任务数、视频链接数、Prompt 数与 manifest/results 一致。
- 删除一次性测试脚本；保留用户资产和无关工作树内容。
